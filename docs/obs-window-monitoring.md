# OBS 窗口场景运行说明

## 真实能力边界

OBS负责连续录像；本地YOLO-World对OBS虚拟摄像头快照做候选检测。
GPT对话模型的升级不会替换本地检测权重。
当前快照通过逐次打开虚拟摄像头采集，有间隙，不是连续30fps推理，不能保证捕获快速下落烟头。
候选会保存原图、带框图和JSON，必须人工审核；还没有完成抛物轨迹、来源窗口判定、关联人员和前后30秒事件片段。
没有候选不代表没有发生事件。需要真实正例与误报样本评估，禁止伪造检测结果。

## 当前画面约定

OBS竖屏输出1080×1920、30fps，已转正，AI配置rotation_degrees=0。
直接分析未经OBS转正的摄像头文件时，应单独核对方向。
拍摄区域需要操作者确认，不自动猜测来源窗口或具体住户。
只保留必要的外部区域，不增加对窗内的观察，不做人脸或住户身份识别。

## 启停AI（不控制OBS录像）

在项目目录执行，先通过 `pgrep -x OBS` 核实本次OBS进程编号：

```bash
python -u -m app.capture.obs_session --obs-pid <已核实的OBS编号>
```

启动器使用设备名而非可变编号，12秒采集超时后重试。AI工作进程每小时重启并重新加载权重。
运行锁防止重复启动；SIGTERM/SIGINT会清理子进程。
OBS退出或外接盘不可用/余量低于10%时，启动器结束，不改写系统盘。
注意：该保护只管理AI，不代替OBS的录制磁盘错误处理，也不会自动停止OBS录像。
停止AI时对已核实的启动器PID发送SIGTERM；停止录像请在OBS点击“停止录制”。
启动器运行时caffeinate临时防止空闲睡眠，不更改系统永久设置。MacBook仍需接电且避免合盖。

## 状态与证据

- `logs/inference.log`：每次实际推理耗时、候选数、输入年龄。
- 外接盘 `snapshots/detections/live_status.json`：最近成功时间、已分析帧数、错误状态。
- `snapshots/detections/camera01_latest_cigarette_detection.jpg`：最近标注图。
- `events/YYYY/MM/DD/`：仅模型输出候选时写入的待审核证据。

必须同时核对状态更新时间；旧的running文件不代表进程仍存活。
超过10秒的旧输入拒绝推理。证据使用推理前固定的同一份图片，JSON含采集时间和SHA256。
没有自动日落停止机制，没有后台云端监控；未设置停止时间时OBS会继续录制直到人工停止或故障。

## 下一步优化（未实施）

1. 确认拍摄区域ROI，检查烟头实际像素尺寸及运动模糊。
2. 在短测试窗口切换Apple VideoToolbox硬件编码，保留更高分辨率/码率原始录像。
3. 引入连续帧小物体运动候选和轨迹，再用局部离线模型复核，不以逐秒快照替代。
4. 用真实事件片段标明漏检、误报及证据可用性后，才评估无人值守运行。
